> [!abstract] 30 秒掌握
>
> - 模型调用只是应用的一环，输入、鉴权、上下文、工具、校验和结果展示仍需要软件实现。
> - SDK 封装接口调用，框架帮助组织流程，都不自动替你解决业务正确性。
> - Rule、Skill 和 Plugin 管理约束、方法与分发，不替代后端、数据库或权限系统。
> - 第一版先完成一个范围清楚、可验证的任务，再按真实问题增加能力。

前置：[[AI 开发/可靠性/验证、评测与执行追踪|验证、评测与执行追踪]]。本文是主线的收束，用一个应用把前面的概念连接起来，不展开部署命令或特定 SDK。

## 1. 一个知识库助手需要哪些部分

| 层次           | 负责什么                 | 最小例子                             |
| -------------- | ------------------------ | ------------------------------------ |
| 界面或调用入口 | 收集问题、展示进度和结果 | 网页输入框，或供程序调用的 API       |
| 应用后端       | 鉴权、组织流程、管理状态 | 判断用户能读哪些文档，组装上下文     |
| 模型服务       | 理解输入并生成输出       | 根据材料回答问题                     |
| 数据与工具     | 获取事实、执行动作       | 检索文章、读取正文；写入能力按需增加 |
| 运行保障       | 校验、观测、限流和恢复   | 检查来源、记录错误、控制预算         |

这些是职责层次，不要求部署成五个独立服务。小应用可以把多种职责放在同一后端；模型和存储则可以使用本地或托管服务。

## 2. 一次请求怎样穿过这些部分

以“项目文档由谁提交”为例：

1. 界面把问题送给应用后端。
2. 后端检查身份和资料权限，检索适用规则。
3. 后端把问题、规则片段和来源交给模型。
4. 模型生成回答，应用检查输出格式及引用是否有效。
5. 界面展示答案和来源；证据不足时展示缺口。

如果用户只是在问规则，这条链不需要写文件，也不必增加自主规划。用户进一步要求修改文档时，才评估所需工具、授权和运行循环。

API 是程序间的接口；SDK 是便于调用接口的代码库；框架可以提供流程、状态或工具集成。它们减少重复工程，但不能自动知道什么是正确的项目答案。

## 3. 模型、检索与微调分别解决什么

初期用代表性任务比较模型的实际效果，再考虑质量、响应速度、费用和数据处理要求，不只看通用榜单。

- **任务要求不清楚**：先调整 Prompt 和验收标准。
- **缺少最新项目事实**：先考虑提供上下文或检索，不用训练替代资料更新。
- **稳定任务上的输出行为仍不理想**：有足够高质量样例后，再评估微调是否有收益。

微调会调整模型参数，但不自动赋予外部权限，也不保证准确记住每条新资料。这些手段可以组合，是否采用取决于评测结果。

## 4. 规则和扩展怎样进入工程

[[AI 开发/基础概念/AI 开发核心概念|行动与编排的核心概念]] 已解释 Rule、Skill、Plugin 和 MCP 的定义。落地时，把它们放回具体问题：

- 团队长期遵循的边界，保存为规则。
- 某类任务可复用的方法，整理为 Skill。
- 需要分发和升级的一组扩展，按产品机制打包为 Plugin。
- 需要标准化连接外部能力时，考虑 MCP；直接调用本地函数或业务 API 也可以使用工具。

这些机制通常是可选组合，不是每个 AI 应用的必备依赖。使用 Codex 时，再进入知识地图的产品专题查看具体文件和加载规则。

## 5. 从演示走向持续可用

部署的含义是让应用在目标环境持续运行，而不仅是在自己电脑上成功回答一次。第一版上线前至少确认：

- 密钥保存在可信后端或密钥管理服务中，不放进网页代码、文章或公开仓库。
- 用户只能访问被授权的资料；日志不会泄露不必要的敏感内容。
- 服务超时、额度不足、空检索结果都有清楚的失败反馈。
- 模型、Prompt、索引和工具版本能够追踪；升级前比较评测结果。
- 有与风险相称的请求限额、预算、备份和恢复方式；长任务可以被停止。

密钥管理、预发布环境和运行保障可对照 [OpenAI 的生产实践指南](https://developers.openai.com/api/docs/guides/production-best-practices)。不同供应商和部署环境的具体操作需分别核对。

一个合适的入门实践是“只读知识库问答”：回答附来源，没有证据就说明不足。确认它可靠后，再逐步增加修改建议、经授权的写入或更复杂编排，不必一开始就搭建包含全部概念的平台。
